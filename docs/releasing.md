# 发布 v0.1 预览版

当前以 Git 源码仓库为完整发行形式。核心 wheel 不包含仓库根目录的插件、示例和启动脚本。不要将单个 wheel 宣传为完整的插件套装。

## 发布前

- 由仓库所有者选择许可证，添加 `LICENSE` 并同步 Python 包元数据。没有许可证不等于授权他人自由使用、修改或分发。
- 确认 `git status --short` 中所有计划发布的文件已纳入提交，包括 `start.bat`；不要添加 `.runtime`、`.venv`、设备日志或真实 MCP 配置。
- 在新目录克隆，按 README 创建虚拟环境并安装 `[test,mcp]`；执行完整测试。GitHub Actions 提供 Windows / Python 3.11、3.12 验证，但新增工作流必须实际运行后才能声明通过。
- 默认安装解析依赖范围。若需要重现锁定环境，在 Windows / Python 3.12 使用 `pip install -r requirements.lock` 后再安装项目；不要将该锁文件当作跨平台保证。
- 在空数据目录启动服务，检查 `/health`、`/docs`，使用生成的 token 查询受保护接口。
- 注册 effects 插件，验证预览创建、数据更新和关闭；通过两个独立 MCP 连接验证同一 session 的变量保留。
- CDP、USB 和 ADB 功能另做真实设备验证。单元测试通过不意味着每个游戏宿主或微信版本兼容。

## 发布内容

建议首个 Release 标注为预览版，写明 Python 3.11+、主要验证平台、可信本机执行边界，以及已知问题。仓库名 `ai-runtime`、Python 发行名 `local-ai-runtime`、导入名 `ai_runtime` 各有用途。

源码压缩包应从已提交的 Git 版本生成，不要直接压缩整个工作目录。后者可能带入 token、执行历史、截图、检查点和本机依赖。

## 用户排错

- `/` 返回 404：当前入口是 `/docs`，不是首页仪表盘。
- API 返回 401：在 Swagger Authorize 填入本次数据目录的 token 内容。
- 插件列表为空：新安装没有预注册插件，先运行 README 的注册命令。
- MCP 无法启动：确认安装了 `[mcp]`，并将示例绝对路径改为本机路径。命令参数应按客户端要求拆为独立参数。
- 服务更新后仍是旧行为：服务进程、现存 kernel 和 MCP Adapter 是不同进程；按更新涉及的部分分别重启。重建 kernel 会丢失变量，不应自动执行。
- 预览失效：服务或所属 kernel 结束后，旧链接不可继续使用；重新创建预览。

提交问题时附 Python/系统版本、操作步骤、插件版本和已脱敏日志。不要上传 `.runtime/token`、完整 `.runtime`、带访问凭证的预览链接或私有项目源码。
